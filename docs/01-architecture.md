## Design Lab (Phase 2) — `lab/`

The selector pages live in one walkable hub, built by the same `node build.mjs`:

```
lab/
├── src/lab.template.html     page shell, CSS, tabs, walk view
├── src/js/30-lab-core.js     engine: LabWalkScene (hero, collisions, lights, darkness, particles),
│                             grid/thumbnails, Pick/Maybe/No + region tags + notes, DB sync
├── src/js/31-lab-towers.js   3 house-style floor plans + furniture rules + 10 tower styles
├── src/js/32-lab-dungeons.js cave generator + 10 open-cavern designs (spawn markers, guardian portal)

├── index.html                built lab (open locally)

```

- The lab reuses the game's `00-header.js`, `01-sprite-data.js` and `02-hero-api.js`, so it walks with the real hero.
- A design is `{id, name, tagline, blurb, build(seed) → map}`; `map` = pre-painted base canvas + depth-sorted
  sprites + lights + particles + solid grid (see `newMap` in 30-lab-core.js).
- Published as the **Zeldara Design Lab** artifact (https://claude.ai/artifact/MnYcjcTXfpWm4YuiErDLHd). Picks
  are stored in its DB, collection `picks`, doc id `<tab>-<designId>`:
  `{tab, id, title, verdict: pick|maybe|no, regions:[1-4], notes}`. Read them with ArtifactData `list`.

## Why a build step

The game used to be one hand-edited 11,366-line HTML file. It is now split into ~20 source files so each
scene/system can be edited on its own and so the selector pages (Design Lab, Phase 2) can reuse the same
code. The build only concatenates: **no bundler, no modules, no transpiling.** The output is byte-identical
in structure to the old single file, still classic `<script>`, still opens from `file://`.

Round-trip check done at the split: building the untouched sources reproduced the original file
byte-for-byte (same md5).

## Tech stack

- **Phaser 3.60** from cdnjs (`<script src>` in the template). Internet needed at first load.
- **Vanilla JS**, classic scripts, one global scope. Top-level `const`/`class` in one `src/js` file are
  visible to later files at runtime (they are concatenated into one script).
- **DOM overlay** UI (HUD, modals) over the Phaser canvas.
- **Save** — `localStorage['qoz_v2']`, versioned (`saveVersion`, see `08-save.js`).
- **Sprites** — PNGs in `assets/hero`, base64-inlined at build time, loaded via `TextureManager.addBase64()`.

## Editing workflow

1. Find the code: `grep -rn "_castSpell" src/js/`.
2. Edit the file in `src/js/` (or `src/body.html`, `src/styles.css`).
3. Build and syntax-check: `node build.mjs --check`.
4. Test: open `index.html` in Chrome, and/or run the headless tests (doc 05).
5. Commit. (Git + Vercel push is parked until the overhaul is stable.)

**Never edit `index.html` directly** — the next build overwrites it.
**Adding a sprite frame:** drop the PNG in `assets/hero/`, add it to `assets/manifest.json`, rebuild.
**Adding a new JS file:** name it with a number so it sorts where it must run (e.g. data before scenes,
`20-game-config.js` before anything that uses `game` at load time).
**A literal `</script>` in JS** breaks the page — the build refuses it; write `<\/script>`.
